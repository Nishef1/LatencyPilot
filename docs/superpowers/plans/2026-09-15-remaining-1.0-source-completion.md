> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move LatencyPilot from the verified internal GPU execution tranche at `bf71682fd63c74fff02ee161db438d7663e4ec06` to the maximum honest 1.0 source-complete state across USB/xHCI, NIC/RSS, cross-subsystem policy/restore and release hardening, while preserving all physical arming gates.

**Tech Stack:** C# 14, .NET 10 LTS, WinUI 3 / Windows App SDK 2.4, Windows Service, SetupAPI/Configuration Manager, documented USB hub IOCTLs, StandardCimv2 RSS provider through `System.Management` 10.0.12 if required, ETW/TraceEvent, PresentMon, SQLite mutation journal, MSTest/Microsoft.Testing.Platform, Inno Setup and PowerShell release tooling.

## Global Constraints

- Work directly on `main`; preserve unrelated work.
- Hosted GitHub Actions remains test-only.
- Public product protocol stays observation-only v6 and mutation stays unavailable/unarmed until the documented physical gates pass.
- No generic privileged shell/process/registry executor, second UI framework, second persistence engine, second IPC stack, generic tweak framework or speculative abstraction.
- Permanent automated tests stay at 10 while that remains coherent. The owner authorizes growth up to 20 only when genuinely necessary to prevent a test source file exceeding 1200 lines or to preserve meaningful durable separation. Temporary tests must be removed and obsolete permanent tests retired rather than accumulated.
- No test source file may exceed 1200 lines.
- Missing/ambiguous Windows evidence is explicit unavailable/inconclusive evidence; never infer ports, queues, processors, MSI ownership, runtime placement or improvement from names/registry hints.
- Source-complete never closes owner-local hardware, App/Service launch, installer, signing, accessibility or physical mutation gates.
