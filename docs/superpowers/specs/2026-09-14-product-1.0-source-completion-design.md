# LatencyPilot 1.0 Source Completion Design

Status: **Approved; repository-verifiable source tranche implemented, physical closure remains**  
Original approval: 2026-09-14  
Reconciled: 2026-09-15

## Goal

The product goal remains a trustworthy Windows 11 latency optimizer that measures first, runs only narrowly supported experiments, preserves raw before/after evidence and can restore every managed change.

`Source-complete` is intentionally narrower than `1.0 complete`:

- **source-complete** — every repository-verifiable 1.0 requirement is implemented and wired, or the remaining implementation is explicitly blocked by a prerequisite physical safety gate;
- **physically closed** — required App/Service/hardware/restart/recovery/UI/package/signing evidence exists on exact recorded artifacts;
- **armed product capability** — system-changing UI/IPC is exposed only after its physical gates pass.

No source or hosted CI result may be used as fictional hardware/package/signing evidence.

## Architecture to preserve

Reuse the existing boundaries:

```text
App → Protocol → Service
App → Platform.Windows (non-privileged local evidence)
Service → Benchmarking + Platform.Windows + Persistence
Benchmarking → Core
Platform.Windows → Core
```

Do not add a second UI framework, persistence engine, IPC stack, generic tweak engine, generic registry writer, generic shell/process executor or speculative abstraction layer.

## Public safety boundary

Until Gate A→B→C→D is satisfied:

```text
Protocol = v6 / LatencyPilot.Observation.v6
Commands = GetStatus, CaptureKernelLatency
MutationAvailable = false
```

Internal mutation/recovery source and the owner-only harness are not product mutation surfaces.

## Implemented source slices

### 1. GPU experiment/recovery source

Implemented and shared across deterministic interpretation/execution boundaries:

- valid repeated baseline plus `workload-stability-v1` readiness;
- bounded topology/pressure-aware GPU affinity candidates;
- exact original affinity snapshot and durable SQLite journal ownership;
- interruption-aware logical two-value affinity write/compensation semantics;
- exact-target activation/restart and reboot-required detection source;
- synchronized ETW + raw PresentMon evidence under one interval/deadline;
- raw DPC primary distribution plus named graphics guardrails;
- exact display-driver ISR runtime-placement verification;
- screening that can only nominate a finalist;
- fixed eight-run `ABBA + BAAB` confirmation;
- explicit Improved/Regressed/Tradeoff/NoMeasurableDifference/Inconclusive interpretation;
- verified Keep or exact RestoreOriginal/RecoveryRequired transitions;
- retained `Kept` changes remain active managed machine state for restore/uninstall safety.

Physical Gate A still owns real restart/apply/effective-placement/forced-failure/rollback proof.

### 2. USB/xHCI/input read-only/readiness source

Implemented:

- Raw Input interface → PnP identity/ancestry → exact xHCI controller;
- documented USB hub enumeration and connection IOCTL source;
- unique driver-key correlation to exact hub/port with ambiguity/unavailability retained;
- bounded Raw Input timing capture that refuses to overwrite an existing process registration;
- host-observable report interval/rate/jitter/gap/burst analysis;
- explicit separation from click-to-photon/physical device latency;
- xHCI module-attributed DPC/ISR readiness metrics and guardrails;
- App read-only inspector surface and explicit on-demand five-second timing action.

A system-changing xHCI/controller affinity path is deferred until Gate A proves the shared mutation substrate physically. This is a safety prerequisite, not an omitted generic writer.

### 3. NIC/RSS read-only/readiness source

Implemented:

- `Root\StandardCimv2` `MSFT_NetAdapterRssSettingData` provider reader;
- provider-status-aware enabled/MSI/MSI-X/queue/message/profile/processor/indirection evidence;
- conservative unique provider→PnP correlation;
- vendor-driver DPC/ISR attribution kept distinct from generic NDIS evidence;
- controlled local RTT/jitter/loss/throughput/CPU metric interpretation;
- Internet observations tagged supplemental only;
- App read-only RSS evidence surface.

A system-changing RSS/affinity path is deferred until Gate A physically proves the shared mutation substrate.

### 4. Cross-subsystem policy and restore

Implemented:

- versioned Competitive/Gaming, General and Audio-sensitive profiles;
- explicit per-subsystem opt-out;
- raw named metrics and guardrails always retained;
- Pareto Dominates/Dominated/Equivalent/Tradeoff/Inconclusive relation;
- no arbitrary weighted score;
- global Restore Baseline newest-first planning;
- fail-closed behavior for unresolved or unknown mutation kinds;
- restoration delegated to narrow subsystem-specific recovery executors.

An armed multi-subsystem optimizer remains gated until supported USB/NIC mutation paths exist and pass their physical prerequisites.

### 5. Release/recovery hardening source

Implemented:

- exact-main/clean-tree/exact-green-tests release identity gate;
- owner-local Release restore/build/publish and WinUI launch-smoke source;
- explicit App/Service/docs/scripts payload assembly;
- canonical SHA-256 payload manifest and package SHA-256 companions;
- Authenticode signing/verification hook using SHA-256 file digests and RFC 3161 timestamps;
- final release requires signing configuration;
- install/upgrade/uninstall preflight preserves recovery tools while retained/unresolved state exists;
- `Kept` is unsafe for removal until restored;
- local redacted diagnostics ZIP with no automatic upload;
- hosted GitHub Actions remains test-only.

Actual Windows build, installer, signing credentials, clean-machine install/upgrade/uninstall, GUI/accessibility and hardware evidence remain owner-local.

## Measurement/readiness contract

Decision-grade optimizer eligibility currently requires:

```text
baseline-quality-v2 = Valid
AND
workload-stability-v1 = Stable
```

`workload-stability-v1` analyzes the same five windows using DPC/ISR event rates and complete CPU-busy evidence when available. Early/late activity drift above 25% or a single-window relative deviation above 50% blocks candidate planning.

A future serialized workload-readiness field requires a new evidence schema version; v8 is not silently redefined.

## Test strategy

- default/target permanent suite: 10;
- current durable suite: 15;
- owner-authorized maximum: 20 only for `<=1200` lines/test-file or materially safer durable separation;
- current USB, input, NIC/RSS, profile/Pareto and restore tests intentionally use that authorization;
- temporary/obsolete tests are removed rather than accumulated.

Hosted CI remains exactly test-only. No hosted WinUI build, Service install/start, installer build, signing or hardware claim is added.

## Physical gate sequence

```text
Phase 2 read-only physical closure
→ Gate A internal GPU substrate proof
→ Gate B mutation-specific typed/allowlisted IPC source
→ Gate C physical App/client → Service mutation proof
→ Gate D user-facing GPU arming
→ supported USB/xHCI mutation implementation + physical proof
→ supported NIC/RSS mutation implementation + physical proof
→ bounded multi-subsystem profile/Restore validation
→ accessibility + signed package/install/upgrade/uninstall/recovery validation
→ representative supported-hardware audit
→ 1.0 tag audit
```

Gate A requires real exact-target restart/reboot behavior, one candidate apply→stored verify→runtime ISR placement→exact rollback, a deliberate supported failure with verified recovery, and final exact original/zero-unresolved state.

## Definition of completion

Repository/source completion is reached when the current source/docs/test-only CI reconcile on one exact final HEAD and every remaining implementation item is explicitly blocked by the physical sequence above.

True product `1.0`/`100%` is reached only after every physical exit gate, mutation arming gate, supported USB/NIC experiment, accessibility/runtime check, signed package/upgrade/uninstall/recovery check and representative hardware audit is complete. No lower bar is implied by this design.
